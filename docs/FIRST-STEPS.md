# Первые шаги: если это ваш первый проект

Это руководство для тех, кто никогда не участвовал в чужом проекте — или
вообще только начинает программировать или рисовать интерфейсы. Возраст и
опыт не важны: если вы читаете это и вам интересно — вы уже подходите.

Ничего не сломается. Всё, что вы меняете, сначала живёт только у вас на
компьютере, потом — в вашей копии проекта, и попадает в Pips, только когда
кто-то посмотрит и согласится. Ошибаться можно и нужно: так учатся все.

Дальше, когда освоитесь, — [GUIDE.md](GUIDE.md): как устроен проект целиком.

---

## 1. Что понадобится

- **Компьютер** с Windows, macOS или Linux. Телефон — для проверки.
- **Редактор кода.** Подойдёт бесплатный [VS Code](https://code.visualstudio.com/):
  он подсвечивает код и сам показывает многие ошибки.
- **Git** — программа, которая помнит все версии файлов. Как «Отменить» в
  редакторе, только для всего проекта и навсегда.
- **Аккаунт на GitHub** — сайте, где лежит Pips и где обсуждают изменения.
- **Node.js** и **Python 3** — чтобы запускать проверки и локальный сервер.
- Для работы с ядром на Rust — ещё **Rust**. Для первых задач (тексты,
  цвета, интерфейс) он не нужен: см. «Без собранного ядра» ниже.

Если что-то не получается установить — это нормально. Спросите (раздел 9).

## 2. Пять слов, которые нужно знать

| Слово | Что это |
|---|---|
| **Терминал** | Окно, куда вводят команды текстом. В VS Code: меню Terminal → New Terminal |
| **Репозиторий** | Папка проекта вместе со всей её историей |
| **Форк** | Ваша копия чужого репозитория на GitHub. В ней можно делать что угодно |
| **Коммит** | Сохранённый шаг: «вот что я изменил и зачем» |
| **Пулл-реквест (PR)** | Просьба: «посмотрите мои изменения и возьмите их в проект» |

## 3. Получить проект к себе

1. На странице проекта на GitHub нажмите **Fork** — появится ваша копия.
2. В терминале:
   ```sh
   git clone https://github.com/ВАШ_ЛОГИН/pips.git
   cd pips
   git checkout unstable          # работа идёт в этой ветке
   git checkout -b my-first-fix   # своя ветка для своей задачи
   ```
3. Запустите приложение:
   ```sh
   scripts/serve.sh
   ```
   и откройте в браузере http://localhost:8000. На Windows вместо этой
   команды: `cd web` и `python -m http.server 8000 --bind 127.0.0.1`.

**Без собранного ядра.** Если Rust не установлен, папки `web/pkg/` не будет —
и на localhost приложение запустится на «заглушке» с надписью DEV STUB. Для
текстов, цветов и интерфейса этого достаточно. Обмен карточками и подписи на
заглушке не настоящие — их проверит CI на GitHub.

**Карточки для опытов**: Профиль → «Для разработчиков» → фраза
`I am a developer` → «Добавить образцы».

## 4. Первая задача: поменять текст

Допустим, вам кажется, что надпись на кнопке можно сказать лучше.

1. Найдите эту надпись в файле `web/src/i18n.js` (в VS Code: Ctrl+Shift+F —
   поиск по всем файлам). Например:
   ```js
   'share.many.file': 'Одним файлом',
   ```
   Слева — **ключ** (имя надписи), справа — сам текст.
2. Поменяйте текст справа. Ключ не трогайте.
3. В том же файле ниже есть английская часть — проверьте, нужно ли поменять
   и её.
4. Обновите страницу в браузере (Ctrl+Shift+R) и посмотрите.
5. Запустите проверку:
   ```sh
   node --test tests/unit/*.test.mjs
   ```
   Если всё хорошо — внизу будет `fail 0`.

Поздравляем: это уже настоящий вклад в проект.

> Тексты Pips пишутся просто и спокойно, без восклицательных знаков и
> канцелярита: «Сохранено», а не «Файл был успешно сохранён!». Если
> действие не удалось — говорим, что случилось и что можно сделать.

## 5. Вторая задача: поменять цвет или отступ

Все основные цвета живут в одном месте — в начале `web/css/app.css`:

```css
--cobalt: #3b5fa8; --cobalt-hi: #6d8fd6;
```

Это **токены** — имена цветов. Код никогда не пишет цвет напрямую
(`#3b5fa8`), а только имя (`var(--cobalt)`). Поэтому поменять цвет акцента во
всём приложении — значит поменять одну строчку.

Вид конкретной части экрана — в её собственном файле стилей:
`web/css/kit/action-bar.css` — панель кнопок внизу, `web/css/editor.css` —
редактор и так далее. Найти, какой файл отвечает за элемент, просто: в
браузере нажмите на элемент правой кнопкой → «Просмотреть код» (Inspect) —
увидите его **класс** (например, `many-way`), а потом найдите этот класс
поиском по проекту.

## 6. Как читать код Pips

Возьмём настоящий файл — круглую кнопку с иконкой, `web/src/kit/icon-button.js`:

```js
// @ts-check                               ← попросить редактор проверять типы
// A round button with an icon, ...        ← что это и зачем (комментарий)

import { h, icon } from '../dom.js';       ← взять готовые функции из другого файла

export function iconButton(o) {            ← компонент — это просто функция
  const badge = h('i', { class: 'ib-badge' });          ← создать элемент <i class="ib-badge">
  const el = h('button', {                               ← создать кнопку
    type: 'button', class: 'ib', 'aria-label': o.label,  ← у кнопки есть имя для незрячих
    onclick: o.onClick,                                  ← что делать при нажатии — решает тот, кто позвал
  }, icon(o.icon), badge);                               ← внутри — иконка и счётчик
  return {
    el,                                                  ← сам элемент, чтобы вставить на экран
    count(n) { badge.textContent = n ? String(n) : ''; },  ← способ поменять число на кнопке
  };
}
```

Что здесь важно:

- `h('тег', {свойства}, ...дети)` — так в Pips создаётся всё, что видно на
  экране. Текст всегда вставляется как текст (`textContent`), а не как HTML —
  это защищает от вредных карточек.
- Компонент получает **данные и действия** (`o.label`, `o.onClick`) и отдаёт
  **элемент и методы**. Он не знает, где он используется. Поэтому его легко
  проверять и переиспользовать.
- Над функциями — комментарии с типами в `/** ... */`. Они помогают
  редактору подсказывать и ловить ошибки до запуска.

Если не понимаете какую-то строчку — это нормально. Поищите по проекту, где
используется функция, и посмотрите на примеры. Или спросите.

## 7. Как дизайнить для Pips

Pips — тихое приложение: в центре внимания карточки, а не интерфейс.
Несколько правил, и почему они такие:

- **Палец больше курсора.** Всё, на что нажимают, — не меньше 44×44
  пикселей. Иначе промахиваются, особенно дети и пожилые люди.
- **Сначала маленький экран.** Рисуйте и проверяйте на ширине 320 пикселей
  (самый маленький телефон), потом 390, потом компьютер. Текст не должен
  обрезаться, кнопки одного ряда — переноситься.
- **Ничто не прыгает.** Когда что-то появляется, исчезает или растёт, то, на
  что человек смотрит, остаётся на месте. Кнопки не уезжают из-под пальца.
- **Всё видно и без цвета.** Выбранное отмечено не только цветом, но и
  рамкой или галочкой. Текст контрастный: светлое на тёмном фоне Pips.
- **Готовые цвета и формы.** Используйте токены (`--text`, `--raise`,
  `--cobalt`…) и существующие кирпичики: кнопки `.btn`, листы снизу, панели.
  Новое — только если старое правда не подходит.
- **Каждому жесту — кнопка.** Если что-то делается свайпом, это же должно
  делаться кнопкой и клавиатурой.
- **Движение — спокойное.** Анимации — пружины из `kit/motion.js`. Если в
  системе включено «уменьшить движение», анимаций нет.
- **Слова — короткие.** Кнопка — глагол или существительное в одно-два
  слова. Пояснение — одной строкой мелко под ней.

Как предложить дизайн: нарисуйте (в Figma, на бумаге, где удобно), сделайте
скриншоты «было — стало» на 320 и 390 пикселях и опишите в задаче на GitHub,
что меняется и зачем. Код можно не писать — хороший дизайн тоже вклад.

## 8. Отправить свою работу

```sh
node --test tests/unit/*.test.mjs        # проверки прошли?
git status                                # какие файлы изменились
git add web/src/i18n.js                   # выбрать файлы
git commit -m "i18n: clearer label for sharing as one file"
git push -u origin my-first-fix
```

Потом на GitHub появится кнопка **Compare & pull request**. Выберите, куда:
ветка **`unstable`** проекта `pips-app/pips`. Опишите:

- что изменили;
- зачем (что было не так);
- как проверили (скриншоты — прямо в описание PR, не в файлы проекта).

Вам могут ответить вопросами или попросить что-то поправить. Это не значит,
что работа плохая, — так проходит любое изменение, даже у самых опытных.

Правила коммитов: первая строка — `часть: что сделано` (по-английски, как в
истории проекта: `git log --oneline` покажет примеры). Ничего личного в
коммитах — ни адресов, ни телефонов, ни ссылок на переписки.

## 9. Если застряли

- Перечитайте сообщение об ошибке целиком — часто в нём есть ответ.
- Поищите по проекту похожий код: скорее всего, кто-то уже делал похожее.
- Посмотрите `DECISIONS.md`: может быть, «странное» поведение выбрано нарочно.
- Откройте **Issue** (задачу) на GitHub и опишите: что делали, что ожидали,
  что получилось. Скриншот очень помогает.

## 10. Если вам помогает ИИ

Пользоваться ИИ-помощником можно и полезно. Три правила:

1. **Дайте ему прочитать `AGENTS.md`** — там правила проекта для ИИ.
2. **Понимайте, что отправляете.** Если не можете объяснить, что делает
   строчка, которую написал ИИ, — спросите его или не отправляйте её.
3. **Не давайте ему секретов**: ключей, паролей, личных данных.

ИИ ошибается уверенно. Проверки (тесты, скриншоты, телефон в руке) — ваши
лучшие друзья, кто бы ни написал код.

## 11. С чего начать

Хорошие первые задачи:

- поправить неудачную формулировку или опечатку (`i18n.js`, документация);
- проверить приложение на своём телефоне и описать, что показалось
  неудобным или странным;
- улучшить перевод на английский;
- нарисовать карточку-образец (`scripts/samples.py`);
- найти место, где что-то обрезается на маленьком экране, и предложить
  исправление.

Спасибо, что пришли. Pips сделан для того, чтобы люди дарили друг другу
маленькие картинки, — и проект тоже растёт от того, что люди дарят ему
своё время.
