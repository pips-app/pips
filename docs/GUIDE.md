# Pips изнутри: руководство для тех, кто впервые открыл проект

Это руководство для человека, который хочет что-то поправить, добавить или
починить в Pips и пока не знает, с чего начать. Читать подряд не обязательно:
разделы 1–3 стоит прочитать один раз, остальное — когда понадобится.

**Если это ваш первый проект** — начните с [FIRST-STEPS.md](FIRST-STEPS.md):
там всё с самого начала, с примерами.

Рядом лежат:

- [README.md](../README.md) — что такое Pips и как его собрать (англ.);
- [web/README.md](../web/README.md) — устройство приложения и правила его кода (англ.);
- [DECISIONS.md](../DECISIONS.md) — **все принятые решения и их причины**. Если
  что-то в Pips кажется странным, ответ, скорее всего, там;
- [AGENTS.md](../AGENTS.md) — инструкция для ИИ-помощников (людям тоже полезно);
- [SECURITY.md](../SECURITY.md) — как сообщить об уязвимости.

## 1. Pips в двух словах

Pips — пиксельные карточки, которыми обмениваются через QR-код. Человек
рисует картинку, подписывает её своим ключом и показывает код; другой телефон
сканирует код, проверяет подпись, и карточка попадает в коллекцию — с
историей: кто нарисовал, кто передал, какой это экземпляр.

Три вещи, на которых держится всё остальное:

1. **Нет сервера.** Нет аккаунтов, нет облака, нет аналитики. Всё хранится на
   устройстве. Карточка уходит, только когда человек сам её отправил.
2. **Всё, что пришло снаружи, проверяется.** Код, файл, ссылка, картинка —
   разбираются строго: что не сходится, отклоняется целиком, а не «чинится».
   Подписи проверяет ядро на Rust.
3. **Сделанное не теряется.** В редакторе отменяется всё, и отмена —
   дерево. Путь карточки: коллекция → архив → корзина (30 дней) → насовсем,
   и удалить безвозвратно можно только кнопкой с подтверждением.

## 2. Из чего состоит проект

```
crates/        ядро на Rust: формат карточки, подписи, QR, импорт картинок, резервные копии
  pips-wasm/   одна «дверь» из ядра в браузер (WebAssembly)
fuzz/          фаззинг всех разборщиков чужих данных
web/           само приложение: HTML + CSS + JavaScript, без сборки и без зависимостей
  src/         код приложения (подробная карта — web/README.md)
  css/         стили; на каждый компонент — свой файл
tests/unit/    быстрые тесты логики приложения (node, без браузера)
tests/e2e/     тесты в настоящем браузере: два «телефона» обмениваются карточками
scripts/       сборка ядра, локальный сервер, сборка сайта, рисование образцов
docs/          это руководство
```

**Ядро** (Rust) отвечает за всё, где ошибка опасна: разбор формата, подписи,
ключи, шифрование копий. **Приложение** (JavaScript) — тонкий слой интерфейса
поверх ядра. Ядро компилируется в `web/pkg/` (эта папка не хранится в git —
её собирает скрипт).

## 3. Как запустить у себя

Нужны: Rust (stable) с целью `wasm32-unknown-unknown`, `wasm-bindgen-cli` той
же версии, что в `Cargo.lock`, Python 3 и Node.js. На NixOS всё даёт
`nix-shell`.

```sh
cargo test --workspace     # проверить ядро
scripts/build-wasm.sh      # собрать ядро для браузера в web/pkg/
scripts/serve.sh           # открыть http://localhost:8000
```

Открыть `web/index.html` двойным щелчком **не получится**: браузер не
запускает модули и WebAssembly со страницы-файла. Нужен сервер.

Полезное:

- **Без собранного ядра** приложение на localhost запускается на заглушке
  (`web/src/stub-core.js`) с баннером «DEV STUB». Криптографии там нет —
  годится, чтобы посмотреть на интерфейс, но не чтобы проверять обмен.
- **Образцы карточек**: Профиль → «Для разработчиков», ввести фразу
  `I am a developer` → «Добавить образцы». Удаляются тем же набором.
- **Телефон**: многое (жесты, камера, системное «Поделиться») по-настоящему
  проверяется только пальцами. Перед слиянием в `main` пройдите изменённое
  на телефоне.

## 4. Как устроено приложение (5 минут)

Представьте слоёный пирог. Каждый слой знает только о тех, что ниже.

1. **Токены** — цвета, шрифты, радиусы (`css/app.css`), пружины анимаций
   (`kit/motion.js`). Своих цветов и кривых анимации компоненты не
   заводят — берут их отсюда.
2. **Чистая логика** — раскладка коллекции, поиск, модель редактора, история
   отмены, формат файлов. Без DOM, проверяется тестами в node.
3. **Кирпичики** (`src/kit/`) — кнопки, листы снизу и сверху, полосы, поля.
   Компонент — это функция: `make(options) → { el, …методы }`. Он не лезет в
   данные приложения и не знает, что значит нажатие, — это решает тот, кто
   его позвал.
4. **Части экранов** — `collection/*.js`, `editor/*.js`, `ui/*.js`.
5. **Экраны** — `collection/view.js`, `editor/view.js`: собирают части и
   решают, что значат жесты.

Два правила, которые важнее остальных:

- **Данные меняются в одном месте.** Карточки, профиль, настройки — только
  через `src/state.js`. Картинка в редакторе — только через
  `editor/model.js`, где каждое изменение — запись в истории. Если вы меняете
  данные где-то ещё, отмена и черновики сломаются.
- **Всё, что видит человек, — текст из `src/i18n.js`**, на двух языках с
  одинаковыми ключами. Никакого `innerHTML`: текст карточек попадает на
  страницу только как текст (иначе чужая карточка могла бы выполнить код).

## 5. «Хочу поменять X — где это?»

| Что | Где |
|---|---|
| Текст на экране, перевод | `web/src/i18n.js` (ключ есть в обоих языках) |
| Цвета, шрифты, общие отступы | `web/css/app.css` (переменные в `:root`) |
| Вид конкретного компонента | `web/css/kit/<имя>.css` или `web/css/<экран>.css` |
| Иконка | `web/src/dom.js` (набор иконок) |
| Коллекция: сетка, лента, масштаб | `collection/layout.js`, `stage.js`, `view.js` |
| Карточка крупно, оборот, теги | `collection/turn.js`, `back.js` |
| Поделиться одной / несколькими | `collection/share.js`, `share-many.js`, `ui/send.js` |
| Архив, корзина, перенос | `collection/moves.js` |
| Сканер, приём кода/файла/ссылки | `ui/scan.js`, `ui/receive.js`, `ui/arrival.js` |
| Редактор: инструменты | `editor/tools.js`, `strokes.js`, `raster.js` |
| Редактор: кадры, слои | `editor/frames.js`, `layers-sheet.js`, `model.js` |
| Что можно подписать (лимиты) | `web/src/budget.js` |

`i18n.js`, возьмите ключ (`'share.many.file'`) и поищите ключ в `web/src`.

## 6. Как правильно починить баг

Баг — это сначала вопрос «почему», и только потом «как».

1. **Воспроизведите.** Запишите точные шаги, размер экрана, браузер. Если не
   воспроизводится — не чините вслепую.
2. **Найдите причину, а не место, где она видна.** Пример из истории
   проекта: кнопки нового листа «не нажимались». Симптом — в листе, причина —
   жесты коллекции перехватывали касания под любым листом. Починка в листе
   спрятала бы баг до следующего листа.
3. **Напишите тест, который падает без починки.** Логика — в
   `tests/unit/`, поведение на экране — в `tests/e2e/app.test.mjs`. Если
   тест написать нельзя (жест пальцами, камера), так и запишите.
4. **Почините** — самым простым из правильных способов. Никаких «подпорок»:
   `setTimeout`, чтобы «успело», `!important`, проверки на конкретный случай.
   Если хочется подпорки — значит, причина ещё не найдена.
5. **Поищите такие же баги рядом.** Ошибка, найденная в одном месте, часто
   повторяется в похожих.
6. **Прогоните все проверки** (раздел 8) и **посмотрите глазами** на узком
   телефоне (320 px), обычном (390 px) и на компьютере.
7. **Если починка — это решение** (выбрали одно поведение вместо другого),
   допишите строчку в `DECISIONS.md`, в раздел про эту часть.

## 7. Как добавить новую функцию

1. **Сначала подумайте и запишите.** Что человек делает, что видит, что
   будет, если он передумает на полпути. Как это работает без жеста
   (кнопкой, клавиатурой)? Что будет на экране 320 px? Как это уживается с
   офлайном и отсутствием сервера?
2. **Посмотрите, нет ли готового кирпичика** в `src/kit/`. Новый компонент
   выносите в `kit/` только когда он понадобился второй раз.
3. **Строки — в `i18n.js`** на оба языка. Тест `i18n.test.mjs` проверит, что
   ключи совпадают и что лишних нет.
4. **Классы CSS** — у каждого один хозяин (модуль, который его создаёт).
   Тест `css-classes.test.mjs` не пустит второго.
5. **Тесты**: логика — unit, путь человека целиком — e2e.
6. **Документация**: `DECISIONS.md` (что решили и почему), `README.md`
   (раздел «What works»), `web/README.md` (если появился новый файл).

## 8. Проверки

```sh
npx --yes -p typescript@5.9.3 tsc -p web/jsconfig.json   # типы во всём JS
node --test tests/unit/*.test.mjs                        # unit-тесты, секунды
cd tests/e2e && npm ci && npx playwright install chromium && npm test   # браузер, минуты
BROWSER=firefox npm test                                 # то же в Firefox
cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace
```

Браузерным тестам нужно собранное ядро в `web/pkg/` (сервер они поднимают
сами). CI на GitHub запускает всё это — Rust, минимальную версию Rust, типы,
unit, e2e в Chromium и Firefox — и публикует сайт только из `main`. Отдельный
процесс прогоняет фаззинг всех разборщиков на каждый push, а раз в неделю —
подольше.

Если тест «иногда падает», это баг — в тесте или в приложении. Не
увеличивайте паузы: ждите **состояния** (появился элемент, исчез лист), а не
времени.

## 9. Ветки, коммиты, релиз

- Работа идёт в ветке **`unstable`**. В `main` её сливает владелец проекта —
  то, что в `main`, сразу публикуется.
- Коммит: `часть: что сделано` (`editor: layers keep their names`), при
  необходимости — тело с объяснением «почему».
- Не переписывайте уже отправленную историю (никакого `push --force`).
- **Ничего личного в коммитах**: ни ссылок на чаты, ни имён, ни адресов.
- Скриншоты и временные файлы — не в репозиторий.

## 10. Опасные места: не трогать без полного понимания

| Что | Почему опасно |
|---|---|
| Формат карточки и конверта (`crates/pips-format`, `pips-sign`) | Карточки уже разосланы. Изменение формата может сделать их нечитаемыми или их подписи — недействительными. Для будущего есть зарезервированный флаг конверта. |
| Шаги хранилища (`web/src/schema.js`) | Выпущенный шаг **никогда не меняется**. Новый формат данных — новый шаг в конце, с тестом. |
| Черновик редактора (`editor/model.js`, `upgradeDraft`) | У людей на устройствах лежат черновики старых версий. Меняете формат — повышайте версию и переводите старый. |
| Адрес сайта и вид ссылок (`web/src/links.js`) | Сменится адрес — сломаются все разосланные ссылки. |
| Content-Security-Policy (`web/index.html`) | Она защищает ключ человека. Никаких сторонних скриптов, шрифтов, счётчиков. |
| Ключ и слова восстановления | Ключ не покидает устройство иначе как в зашифрованной копии или на бумаге по явному действию. |
| Офлайн-кэш (`web/sw.js`) | Ошибка — и у людей «застрянет» старая версия. Список файлов генерируется, руками его не вести. |
| Файл нескольких карточек (`web/src/bundle.js`) | Читает чужие файлы: каждый предел проверяется до использования. Ослаблять проверки нельзя. |

## 11. Грабли, на которые уже наступали

- **Жесты под листами.** Коллекция ловит касания на всём экране. Всё, что
  лежит поверх (листы, диалоги — `[role="dialog"]`), исключено из её
  жестов. Новый слой поверх должен быть диалогом или попасть в этот список.
- **Один класс на два модуля.** CSS общий: `.ed-layer` в одном модуле
  стилизовал чужие элементы. Тест теперь ловит такое.
- **Размер, скопированный из CSS в JS.** Поменяли отступ в CSS — а JS считает
  по-старому. Число, нужное и стилю, и коду, живёт в CSS-переменной и
  читается (`cssNumber` в `dom.js`).
- **Кнопки, которые уезжают.** Список растёт — кнопки под ним съезжают.
  Кнопки листа — в его подвале (`sheet.foot`), прокручивается только список.
- **Рамка выделения снаружи.** Обводка, нарисованная снаружи элемента,
  залезает в промежуток между соседями и сталкивается с их обводкой. Обводку
  выбранного рисуйте внутри (`inset`).
- **Узкий экран.** Три кнопки в ряд на 320 px переносились на две строки.
  Проверяйте каждое новое место на 320 px.
- **Firefox.** Фокус с клавиатуры и некоторые события ведут себя иначе —
  поэтому e2e идут и в нём.
- **Положение элемента на странице — не место карточки.** Коллекция не рисует
  карточки за краем экрана, и их элементы остаются там, где были нарисованы
  последний раз. Где карточка на самом деле, знает сцена (`c.rr` в
  `stage.js`); у элемента спрашивать нельзя. И каждое свойство задаёт
  кто-то один: видимость карточек — только сцена, а не соседние модули.
- **Тест читает тост слишком рано.** Ждите текста (`textMatching`), а не
  паузу.

## 12. Как писать код здесь

Правила — вместе с причинами. Если правило мешает сделать правильно — обсудите его,
а не обходите молча.

- **Сначала прочитайте, потом пишите.** Файл, который меняете, — целиком, и
  тех, кто его вызывает. Большинство ошибок — от изменения, сделанного «по
  кусочку».
- **Маленькие функции с понятными именами.** Имя говорит, *что* получится
  (`copyEnvelope`, `unpackBundle`), а не *как*. Если для объяснения функции
  нужно слово «и» — возможно, это две функции.
- **Чистая логика — отдельно от экрана.** Всё, что можно посчитать без DOM
  (раскладка, разбор файла, модель редактора), живёт в своём модуле и
  проверяется unit-тестом за миллисекунды.
- **Комментарий объясняет «почему».** «Увеличиваем i» — бесполезно. «По
  одному: дюжина больших файлов разом заняла бы всю память» — полезно.
  Код и комментарии пишутся по-английски, простыми предложениями.
- **Число с именем и причиной.** Не `250`, а `const MAX_PICTURES = 20` и
  строчка рядом: откуда 20.
- **Чужим данным не верить.** Всё из файла, кода, ссылки: проверить размер
  до чтения, длину до использования, отказать целиком, если не сходится.
  Ошибку не глотать молча: либо сказать человеку, либо записать в журнал
  (`caught` из `diagnostics.js`).
- **Асинхронность — аккуратно.** Пока ждём (файл, картинку, подпись),
  человек может нажать ещё раз или уйти. Кнопка на это время выключается
  (`disabled`), а прежде чем показать результат, код проверяет, что экран
  ещё тот же.
- **Без новых зависимостей.** Ни npm-пакетов в приложении, ни CDN. Нужна
  функция — напишите маленькую свою или возьмите из ядра.
- **Типы проверяются.** `tsc` должен проходить без ошибок; `any` — только
  с объяснением, почему иначе нельзя.
- **Удаляйте лишнее.** Неиспользуемая функция, строка, класс — удаляются
  сразу. Тесты `i18n` и `css-classes` напомнят.

## 13. Как дизайнить здесь

Подробно и для начинающих — в [FIRST-STEPS.md](FIRST-STEPS.md#7-как-дизайнить-для-pips).
Коротко:

- Всё, на что нажимают, — от 44×44 px. Проверка — 320×568, 390×844, компьютер.
- Ничего не сдвигается под пальцем и взглядом: кнопки листа — в его подвале,
  обводка выбранного — внутри элемента, место под подсказки зарезервировано.
- Только токены из `css/app.css` и кирпичики из `src/kit/`.
- Выбранное видно не только цветом. Текст контрастный.
- Каждому жесту — кнопка и клавиша. Escape закрывает только верхнее.
- Сказать, а не промолчать: если действие невозможно — короткая фраза почему.
- Движение — пружины из `kit/motion.js`; при «уменьшить движение» — без него.

## 14. Как работать над задачей

1. **Поймите, зачем.** Кто это заметит и что у него изменится?
2. **Разбейте на маленькие шаги**, каждый из которых можно проверить.
3. **Делайте по одному шагу** и проверяйте после каждого — так ошибка всегда
   в последнем шаге, а не «где-то».
4. **Один коммит — одна мысль.** Несвязанные изменения — отдельно.
5. **В конце — как ревьюер.** Прочитайте свой `git diff` целиком так, будто
   это написал кто-то другой. Найдётся что-то почти всегда.
6. **Расскажите честно**: что сделано, что проверено, что не удалось
   проверить и почему.

| Карточка | Картинка + название + автор, подписанная ключом автора |
| Payload | Байты карточки, как их подписал автор; хранятся как пришли |
| Digest | Отпечаток карточки — её имя для сравнения «уже есть» |
| Конверт | Карточка + все подписи на пути (автор, передавшие). Уходит любым путём: QR, файл, ссылка, картинка |
| Экземпляр | Номерная копия («№3 из 50»), выданная автором конкретному человеку |
| Карусель | Несколько QR-кадров по очереди — для крупных карточек |
| Бандл | Файл `.pips` с несколькими конвертами (`bundle.js`) |
| Место | Коллекция, архив или корзина |
| Уровень | Масштаб коллекции: месяцы → недели → лента → карточка |
| Кадр, длительность | Кадр анимации; длительность — сколько тактов он держится |
| Слой, клетка (cel) | Слой картинки в редакторе; клетка — слой в одном кадре |
| Ядро | Код на Rust (`crates/`), в браузере — WebAssembly из `web/pkg/` |
